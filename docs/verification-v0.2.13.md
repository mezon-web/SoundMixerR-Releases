# SoundMixerR v0.2.13 検証結果

実施日：2026-11-01。Windows 11 x64、.NET SDK 10.0.402、.NET 10 / WPF、NAudio.Wasapi 3.3.0でローカル検証しました。GitHub Actionsは使用していません。

## 確認できたこと

- Releaseビルドは警告0・エラー0。自動検査379件成功、1件スキップでした。
- 異なる2つの出力機器へ無音WASAPIストリームを作り、アプリの出力先に対応する音量・ミュート、複数セッションの比率、出力変更後の操作先、古い命令の拒否を確認しました。
- 音声系の検査で変更した12対象は、元の設定へ戻ったことを読み戻して確認しました。
- 設定保存・失敗・キャンセル、外部変更、アプリの固定と名前順、機器切断・変更失敗、編集中の候補保持を検査しました。
- 設定・詳細のモーダル動作、最小化設定ON/OFF、表示復元、ヘッダーの×による終了を検査しました。
- 暗色テーマ、バーと星の配置、コンパクト／ゆったり表示、100～200%相当のWPF描画を検査しました。短い名前・警告なしの詳細画面は折りたたみ223 DIP、展開321 DIPでした。
- ランタイム同梱ZIPを展開し、通常起動・トレイ起動・二重起動・終了の4モードが成功しました。
- ZIPにアプリのソース・ソースZIP・ユーザー設定・ログ・PDBが含まれないことを確認しました。配布文書と自作DLLに現在のユーザーフォルダー・チェックアウトの絶対パス・PC識別名が混入していないことを検査しました。

## 未確認のことと制限

- 入力機器がないため、実アプリ別の入力先変更を1件スキップしています。実際のマイク録音・送信も未検証です。
- 音声の検査は無音ストリームです。実音が別機器へ移動したことの証明ではありません。
- GUI検査は隔離Windowsデスクトップ上のWPFイベント・描画・ネイティブウィンドウ状態によるものです。ユーザーの入力デスクトップは切り替えていません。
- 物理マウス・キーボード操作、実タスクバーのクリック、実OSのDPI変更、複数モニターをまたぐ物理操作、長時間安定性は未検証です。
- アプリ独自の機器指定、排他モード、ASIOなど、Windows共有ミキサーを通らない音声は反映されない場合があります。非公開APIを使うアプリ別の機器設定は、Windowsの更新によって対応状況が変わる可能性があります。
